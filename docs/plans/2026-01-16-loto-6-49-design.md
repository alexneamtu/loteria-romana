# Loto 6/49 + Noroc Design

**Goal:** Add a parallel 6/49 + Noroc pipeline that ingests loto.ro results, trains statistical and neural samplers, backtests them without leakage, and outputs two 6/49 variants per run.

**Scope:** Only Loto 6/49 and Noroc from loto.ro. No other games. The pipeline mirrors Joker behavior but targets 6 main numbers (1-49) plus a Noroc number.

## Architecture

- Parser: extract 6/49 main numbers and Noroc from loto.ro results HTML.
- Storage: cache HTML in `data/raw/loto_6_49_results.html` and append clean draws to `data/clean/loto_6_49_draws.csv`.
- Strategies: random, frequency-weighted (full-history +1 smoothing), and a softmax neural baseline adapted to 49 main numbers.
- Backtest: rolling frequency to avoid leakage; strategy selection based on historical hit count.
- Picks: generate two variants (A/B) per run; honor `--seed` or env seed for determinism.

## Data Flow

1. Fetch results HTML (or read cache).
2. Parse into structured draws: date, 6 main numbers, Noroc number.
3. Append new draws to CSV (skip existing dates).
4. Generate candidate lines for each strategy.
5. Backtest and select best strategy.
6. Output two 6/49 variants with Noroc.

## Error Handling

- Skip incomplete draws (missing numbers or date).
- If no draws exist, output empty results and exit cleanly.
- Invalid seed values produce a clear CLI error.

## Testing

- Parser test with HTML fixture for 6/49 + Noroc.
- Storage tests for dataset update and append behavior.
- Strategy tests: valid ranges and frequency counts.
- Neural sampler tests: softmax validity and output ranges.
- Backtest test to verify rolling history use.
- Picks test for deterministic output when seeded.

## Limitations

- No strategy can improve expected value; outputs are for experimentation.
- Noroc selection rules will follow loto.ro presentation, with uniform sampling unless rules require otherwise.
